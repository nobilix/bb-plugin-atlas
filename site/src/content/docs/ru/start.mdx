В этом руководстве вы создадите плагин по шаблону `bb plugin new`, установите его в bb, опробуете тремя путями и измените код на лету. Шаблон — это рабочий список задач с одним хранилищем и тремя путями доступа: страницей на боковой панели, командой `bb hello` и скиллом, который учит агента вызывать эту команду. Каждая его часть напрямую повторяет архитектуру из статьи [Как работает плагин](/ru/architecture/) — предполагается, что вы её уже прочитали.

Вам понадобятся запущенный bb 0.49 и npm. Держите под рукой [макет зон](/ru/map/), если хотите видеть, где именно в окне находится каждая поверхность.

## 1. Создайте плагин

```console
$ bb plugin new hello
Created bb-plugin-hello/ (bb-plugin-hello).
Installed dependencies (npm install).
Next steps:
  cd bb-plugin-hello
  bb plugin install .
```

Команда сама установит зависимости. Если на этом шаге возникнет ошибка, в выводе среди дальнейших инструкций появится `npm install --include=dev` — выполните её перед шагом 5.

У команды нет флагов. Пакет называется `bb-plugin-hello`, и bb получает идентификатор плагина `hello`, отбрасывая префикс `bb-plugin-`. Этот идентификатор используется в URL страницы, в пути к хранилищу и в имени команды CLI.

## 2. Найдите точки входа в шаблоне

В шаблоне четыре основных файла плагина и три каталога с UI-кодом, который вы можете свободно менять.

- `package.json` — манифест: описание npm-пакета и блок `bb`, объявляющий две точки входа: `server.ts` и `app.tsx`.
- `server.ts` — серверная точка входа: хранилище списка задач, четыре RPC-метода и команда `bb hello`.
- `app.tsx` — клиентская точка входа: страница «Example todos» на боковой панели.
- `skills/example-todos/SKILL.md` — объясняет агенту, какие команды `bb hello` существуют и когда их вызывать.
- `components/ui/`, `hooks/` и `lib/` — скопированные компоненты shadcn и вспомогательные функции, которые можно свободно менять под свои нужды.

Все созданные файлы, поля манифеста и правила для зависимостей описаны в разделе [Анатомия пакета](/ru/package/).

## 3. Разберите серверную точку входа

Откройте `server.ts`. В упрощённом виде его структура выглядит так:

```ts
// server.ts, abridged
export const rpcContract = defineRpcContract({
  todos_list: { input: z.null(), output: z.object({ todos: z.array(todoSchema) }) },
  todos_add:  { input: z.object({ title: z.string().trim().min(1).max(200) }), output: todoSchema },
  // todos_set_done, todos_remove
});

export default async function plugin(bb: BbPluginApi) {
  const writeTodos = async (todos: Todo[]) => {
    await bb.storage.kv.set("todos", todos);
    bb.realtime.publish("todos-changed", { count: todos.length });
  };

  bb.rpc.register(rpcContract, { todos_list: …, todos_add: …, /* … */ });
  bb.cli.register({ name: "hello", commands: [/* list, add, done, undo, remove */], async run(argv) { … } });
  bb.onDispose(() => { bb.log.info("disposed"); });
}
```

Экспорт по умолчанию — это фабрика из статьи [Как работает плагин](/ru/architecture/). Она регистрирует четыре метода RPC и одну команду CLI, причём оба пути вызывают одни и те же вспомогательные функции поверх `bb.storage.kv`. Каждая запись завершается вызовом `bb.realtime.publish`, уведомляя все открытые страницы об изменении списка. Контракт экспортируется, чтобы `app.tsx` мог импортировать его тип.

## 4. Разберите клиентскую точку входа

Откройте `app.tsx`. Страница запрашивает список у сервера по RPC и запрашивает его снова при получении сигнала:

```tsx
// app.tsx, abridged
function useTodos() {
  const rpc = useRpc<typeof rpcContract>();   // typed by the server's contract
  // rpc.call("todos_list") on mount, and again on every "todos-changed" signal
  useRealtime("todos-changed", refetch);
  …
}

function TodosPage() {
  const { rpc, todos, refetch } = useTodos();
  …
}

export default definePluginApp((app) => {
  app.slots.navPanel({
    id: "example-todos", title: "Example todos", icon: "ListTodo",
    path: "example-todos", component: TodosPage,   // route /plugins/hello/example-todos
  });
});
```

`app.slots.navPanel` добавляет пункт на боковую панель bb и выделяет плагину отдельную страницу. Файл импортирует только тип `rpcContract`, поэтому серверный код не попадает в бандл для браузера. React и SDK тоже не попадают в бандл: bb предоставляет их во время выполнения, поэтому `app.tsx` работает только внутри bb.

## 5. Установите плагин и опробуйте его в трёх местах

```bash
cd bb-plugin-hello
bb plugin install .   # a path install: bb builds server.ts and app.tsx itself, no bb plugin build
bb plugin dev         # leave running: rebuilds and reloads on every save
```

`bb plugin install` предупредит, что плагины работают с полным доверием, и запросит подтверждение — ответьте `y`. Если запустить команду вне интерактивного терминала, она завершится отказом, если не указать флаг `--yes`. После установки `bb plugin list` покажет статус `hello@0.1.0  running`.

Теперь опробуйте плагин тремя способами, заложенными в шаблон:

1. В bb откройте **Example todos** на боковой панели и создайте задачу.
2. В терминале выполните `bb hello add "Ship it"`. Новая задача появится на странице без перезагрузки: при записи команда опубликовала сигнал `todos-changed`.
3. В треде попросите агента добавить задачу. Скилл подскажет ему вызвать `bb hello add`, так что изменение пройдёт ровно по тому же пути, что и команда из терминала.

{/* DiagramBoard: quickstart-wiring */}

Все три пути ведут в один и тот же `server.ts`, и ни один из них не обращается к хранилищу напрямую. Логи плагина можно смотреть командой `bb plugin logs hello -f`, а статус проверять через `bb plugin list`.

## 6. Внесите изменения

Добавьте команду `count`. В файле `server.ts` добавьте запись в список `commands` и ветку в `switch` внутри функции `run`:

```ts
commands: [ /* … */ { name: "count", summary: "Count todos", usage: "bb hello count" } ],

case "count": {
  const todos = await listTodos();
  return { exitCode: 0, stdout: String(todos.length) };
}
```

Сохраните файл. `bb plugin dev` выведет `reloaded hello`, а `bb hello count` напечатает количество задач. В выводе `bb plugin logs hello` сообщение `loaded` для нового экземпляра появится раньше, чем `disposed` для старого — именно такой порядок перезагрузки описан в разделе [Как работает плагин](/ru/architecture/).

bb считывает список `commands` без запуска вашего кода и добавляет `bb hello count` в автоматически сгенерированный скилл для команд плагинов. Вручную нужно обновить два текста: строку `usage` в `server.ts`, которую печатает `bb hello --help`, и таблицу команд в `skills/example-todos/SKILL.md` — скилле, который агент загружает для этого плагина.

## Если что-то не работает

| Проблема | Причина | Решение |
|---|---|---|
| Не резолвится `@get-bb/plugin-sdk` | Не установлены типы SDK | Запустите `npm install --include=dev`; внутри монорепозитория bb — `pnpm exec turbo run build:types --filter=@get-bb/plugin-sdk` |
| Порталы, тосты или фокус ведут себя странно | Подменяемый пакет вроде React или radix оказался в `dependencies`, из-за чего в бандл попала его вторая копия | Перенесите все пакеты из `RUNTIME_SLOT_BY_SPECIFIER` в `devDependencies`; `zod` должен остаться в `dependencies` |
| Плагин остаётся в статусе `needs-configuration` | Плагин вызвал `bb.status.needsConfiguration(...)` либо сервис упал с ошибкой `NeedsConfigurationError` | Исправьте конфигурацию и выполните `bb plugin reload hello` |
| SDK старее запущенной версии bb | Шаблон закрепил версию SDK того bb, который его создал | Выполните `bb plugin types`; команда `bb plugin types --check` выполняет ту же проверку в CI без записи файлов |

## Что дальше

- Чтобы понять, куда именно поместить задуманную функцию — в интерфейс или в агента, прочитайте раздел [Выбор поверхности](/ru/choose/).
- Чтобы сохранить секрет, объявите настройку с параметром `secret: true`: её значение никогда не попадёт в клиентскую точку входа. Подробности — в описании [`bb.settings`](/ru/backend/settings/).
- Чтобы отрисовать компонент прямо в ответе агента, используйте слот [`messageDirective`](/ru/frontend/messageDirective/).
- Чтобы задать пользователю вопрос из CLI или из инструмента, посмотрите [`bb.ui`](/ru/backend/ui/) и слот [`pendingInteraction`](/ru/frontend/pendingInteraction/), а также паттерн «предложить и подтвердить» в разделе [Модель доверия](/ru/trust/).
