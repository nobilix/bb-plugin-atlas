bb — это три вида процессов: сервер, который хранит всё состояние, окно приложения, в котором вы работаете, и host daemon на каждой машине, где агент выполняет работу. Плагин добавляет код в один или несколько из этих процессов. Эта страница описывает процессы и объекты, которые bb в них держит; страница [Как устроен плагин](/ru/architecture/) затем размещает среди них код плагина.

## Три процесса

Сервер — процесс Node с SQLite как источником истины. Он хранит каждый проект, thread, настройку и установленный плагин, обслуживает HTTP API и один WebSocket и по умолчанию слушает `127.0.0.1`. Все остальные части bb добираются до состояния через сервер.

Окно приложения — клиент сервера: веб-клиент, десктопное приложение или мобильный клиент. Оно запрашивает данные у сервера по HTTP и получает изменения push-уведомлениями через WebSocket. CLI `bb` — клиент того же сервера, как и агент, который добирается до bb через CLI и через инструменты и skill'ы, выданные ему bb. Когда агент запускает `bb hello add`, команда проходит тот же путь, что и набранная человеком.

Host daemon работает на каждой машине, которая выполняет работу, включая собственную машину сервера. Он запускает процесс агента, который bb называет провайдером агента, держит workspace-каталоги, в которых работают thread'ы, и поддерживает WebSocket-сессию с сервером. Машина, созданная провайдером машины, запускает собственный установленный демон, и тот проходит enrollment на сервере.

## Чем управляет bb

**Проект** группирует работу вокруг репозитория и хранит его `gitRemoteUrl`. Работа вне какого-либо проекта всё равно идёт в проекте — в персональном, `kind: "personal"`.

**Thread** — единица работы. Он содержит один разговор с провайдером агента и порождает append-only поток событий, который окно приложения рендерит как timeline. **Ход** — один обмен внутри thread'а, от сообщения, которое отправил пользователь, до конца ответа агента. Standard-thread делает работу сам; manager-thread координирует другие thread'ы.

**Окружение** — место, где исполняется thread: workspace-каталог, привязанный к одному host. Unmanaged-окружение указывает на уже существующий каталог; managed-окружение, например git worktree, создаётся для thread'а и удаляется, когда его больше не использует ни один неархивированный thread.

**Host** — долгоживущая идентичность демона одной машины. Собственная машина сервера — `primaryHostId`. **Машина** — то, что провижинит провайдер машины; когда её демон проходит enrollment, она появляется как host.

Эти объекты — словарь plugin API. Провайдер окружения готовит workspace на host, событие жизненного цикла thread'а сообщает о завершённом или упавшем ходе, а панель в окне приложения узнаёт текущий проект и thread из `useBbContext()`.

## Собственные функции bb — плагины

Почти всё, что видно в окне приложения, и почти всё, что умеет агент, — плагины на том же публичном SDK, которым пользуется сторонний плагин. Провайдеры агентов для Claude Code, Codex, Pi и ACP-агентов — плагины; плагины и окружения на git worktree, отслеживание задач, интеграция с GitHub и вопросы с вариантами ответа, которые агент задаёт в thread'е. bb поставляет 36 first-party плагинов и 9 примеров, все они перечислены в [каталоге](/ru/plugins/).

Правило за этим сформулировано в дизайн-документах репозитория: ядро владеет минимумом, и «every special case is a public primitive or is deleted». Ядро «never branches on a provider id».
{/* permalink: docs/provider-plugin-api.md */}

Для автора плагина отсюда два следствия. Любая функция, которую вы видите в bb, — свидетельство того, что плагин может сделать нечто похожее через API, который можно прочитать. И быстрее всего изучить API, открыв first-party плагин, который его использует; страница [Выбор поверхности](/ru/choose/) сопоставляет идеи с этими плагинами.
