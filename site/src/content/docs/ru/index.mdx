Этот сайт объясняет, как работают плагины bb, и документирует каждую поверхность, которую они могут занимать. **bb** ([getbb.app](https://getbb.app)) — это открытая «агентная IDE, которая пишет сама себя». Она состоит из Node-сервера, где база SQLite служит источником истины, демона хоста на каждой машине-исполнителе, клиентского приложения (веб, Electron, мобильное) и CLI `bb`. Почти всё, что вы видите в интерфейсе, и почти всё, что делает агент, — это плагины на едином публичном SDK. Этому SDK и посвящён сайт.

## Порядок чтения

Прочитайте первые четыре страницы по порядку. Каждая опирается на предыдущую: от работы bb в целом до кода конкретного плагина.

1. [Как работает bb](/ru/concepts/): три процесса и объекты, которыми управляет bb.
2. [Как работает плагин](/ru/architecture/): три точки входа, как они общаются, где хранится состояние и что происходит при перезагрузке.
3. [Ваш первый плагин](/ru/start/): как сгенерировать шаблон плагина, установить его, вызвать из трёх мест и доработать.
4. [Выбор поверхности](/ru/choose/): как пройти путь от идеи до подходящей поверхности и найти плагин из поставки bb, чей код стоит изучить.

Затем держите справочник открытым во время разработки. Он сгенерирован по коду закреплённого релиза bb, поэтому если страница не соответствует коду, она ломает сборку:

- **[Поверхности](/ru/surfaces/)**: все места, где плагин может появиться или выполнить действие.
- **[Фронтенд-слоты](/ru/frontend/)**: точки регистрации — через них клиентская точка входа получает доступ к поверхностям.
- **[Бэкенд-неймспейсы](/ru/backend/)**: члены API плагинов, которые передаются серверной точке входа.
- **[Макет зон UI](/ru/map/)**: те же поверхности, пронумерованные прямо на настоящем окне.

## Как читать этот справочник

Каждый символ на сайте получил один из двух статусов, и только они отмечены цветной точкой:

- `stable`, изумрудная: в имени нет префикса, а ломающее изменение потребует новой мажорной версии.
- `experimental_`, кобальтовая: префикс встроен в само имя, а в `docs/api_to_audit.md` описано, что нужно проверить перед удалением префикса.

Если члены в карточке частично стабильны, а частично носят префикс, на ней стоят оба статуса. Обычный тег без точки — это просто метка (имя члена, тип слота или роль поверхности), которая ничего не говорит о стабильности.

Любое имя, путь или число — это ссылка на закреплённый коммит на GitHub, вплоть до точной строки кода, если она известна. Ссылки генерируются из `data/symbols.json`, а не пишутся вручную. Идентификаторы, пути, команды и строки интерфейса bb всегда совпадают с кодом в репозитории. Там, где исследование не смогло подтвердить факт, указано **не проверено** — без догадок.

## Кнопки брифов для агента: что попадает в буфер обмена

В каждой карточке поверхности, слота, неймспейса и расширенной точки регистрации есть три кнопки. Каждая копирует готовый контекст для агента, который будет писать плагин.

| Кнопка | Что копирует в буфер | Куда вставлять |
|---|---|---|
| **Brief for agent** | Бриф в Markdown: суть возможности, точка входа, точный вызов при регистрации, тип пропсов, тип слота, стабильность, символы SDK с путями и номерами строк, подходящий плагин из поставки bb, частые ошибки и критерии приёмки | Любой терминальный агент (Claude Code, Codex, Cursor): отправьте первым сообщением в задаче. |
| **as a bb mention** | Тот же формат, что выдаёт встроенный Plugin Guide: `text/plain` с `Build a plugin that uses @<Title>`, плюс `text/html` с `data-prompt-mention`. В композере bb это станет полноценным упоминанием поверхности. | В композер bb, если включён плагин `plugin-api-docs`; иначе вставится как обычный текст. |
| **add to set** | Добавляет поверхность в набор. Панель в правом нижнем углу копирует **один** общий бриф для всех выбранных возможностей: шаблон, архитектуру, по блоку на каждую возможность, общие правила и чеклист. | Используйте для плагина, который делает несколько вещей сразу: так вы отправите один запрос вместо трёх. |

Выбранный набор сохраняется при переходах по страницам и перезагрузке (`localStorage`). Ссылки «open in bb», в том числе на встроенный Plugin Guide, ведут в приложение bb, запущенное на этой же машине (`http://localhost:38886`).
