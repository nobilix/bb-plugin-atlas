Хост-воркер выполняет собственный код на Node на зарегистрированной машине: файлы, wake lock, процессы. В примере ниже объявляется один обработчик, а из того же артефакта реэкспортируется мост провайдера.

```ts
// examples/plugins/echo-provider/host.ts — one artifact, both halves
import { experimental_defineHostEntry } from "@get-bb/plugin-sdk/host";
export { experimental_providerBridge } from "./src/provider-bridge.js";   // the bridge rides along
export default experimental_defineHostEntry({
  contract: echoProviderHostContract,
  handlers: {
    hostGreeting: (_input, context) => ({
      platform: process.platform,
      dataDir: context.experimental_paths.dataDir,
    }),
  },
});
```

**Контекст обработчика.** `signal` (прерывается при отмене запроса или при dispose воркера), `lifecycle.signal` (прерывается один раз за всё время жизни процесса воркера), `experimental_paths.{dataDir,tempDir}`, `experimental_emitSignal(name, payload)`, `experimental_watch(options, listener)` поверх нативного вотчера демона и `experimental_retainWorker()` с disposable lease.

**watch.** События: `{kind:"changed", changes}`, `{kind:"rescan-required"}`, `{kind:"watch-error", message}`; по умолчанию: `debounceMs` — 75, `maxWaitMs` — 500; лимиты: 4096 изменённых путей и 1 МиБ на пачку, 4096 записей ignore и путь не длиннее 16 КиБ.

**Что ещё есть в `/host`.** Контракт нативных корней (`experimental_nativeRootsHostContract`, `experimental_filterResolvedNativeRoots`), функции чтения корней сторонних плагинов (`experimental_resolveClaudePluginRoots`, `experimental_resolveVendorPluginRoots`), `experimental_killProcessesWithCwdUnder` (SIGTERM, затем SIGKILL для каждого процесса, чей cwd находится внутри любого из указанных каталогов), `experimental_readProcessIdentity` (командная строка процесса и время старта, чтобы подтвердить сохранённый PID перед отправкой сигнала), `experimental_sanitizeInheritedChildProcessEnv`, `experimental_spawnPortableOutputProcess` и `experimental_runVcsProcess`. Модуль `@get-bb/plugin-sdk/process` запускает процессы хоста так же, как сам bb: `experimental_hostToolchain`, `experimental_spawnHostProcess`, `experimental_forkHostProcess`, `experimental_execHostFile`.

**Паттерн для прогресса выполнения.** Сервер передаёт хосту `operationId` вида `create#${pathKey}#${attempt}`, хост помечает им свои сигналы, а сервер перенаправляет каждый сигнал в нужный `report` и удаляет запись в `finally`.

**Окружение.** Хост-воркер получает «a normalized user `PATH` without the daemon-owned `BB_*` variables». Это мера гигиены, а не граница безопасности. Для `stdin`/`stdout` задан режим `ignore`, наружу уходит только stderr через логи предупреждений демона с ограничением по частоте (16 КиБ на строку, 1000 строк).
