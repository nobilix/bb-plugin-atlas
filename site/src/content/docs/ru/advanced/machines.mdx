Провайдер машины позволяет плагину выделять вычислительные ресурсы. Обязанности между плагином и ядром строго разграничены: «Core owns enrollment, durable launches, cleanup retries and lifecycle transitions. Plugins own allocation, filesystem preservation and idle policy.» и «Machine plugins do not clone projects.»

Когда новая машина подключена, ядро само настраивает git remote проекта и регистрирует его источник, и только после этого вызывает провайдер окружения, которому нужен `projectCheckout`. К проекту машина не привязана: «nothing about creation names one, and projects reach a machine later through project sources».

**Порядок.** `validate`/`availability` (оба опциональны) → `create` (идемпотентен по ключу) → `await checkpoint(resource)` → `bootstrap({ key, executor, report, signal })` → возврат `{ status:"created", name, resource }`. Задавайте `ephemeral: true` только для временных вычислительных ресурсов: тогда ядро удалит машину, как только она перестанет быть нужна активным тредам.

**Удаление.** `remove({ hostId, resource, … })`, когда чекпоинт существует; `reconcileCleanup({ key, … })`, когда его нет: «Reconcile and remove an uncertain allocation by durable key without creating or bootstrapping. Return failed while allocation intent remains unresolved.» Неудачная очистка сохраняется и повторяется каждую минуту, пока не завершится успехом. При удалении постоянной машины ядро сначала удаляет её окружения через их провайдеры; при удалении эфемерной машины очистка через провайдеры окружений пропускается, а приостановленные вычислительные ресурсы никогда не возобновляются.

**Простой.** За временем простоя следите вы, а не ядро: продлевайте дедлайн через `experimental_thread.events` + `experimental_terminal.input`, очищайте ресурсы через `bb.background.schedule` со сверкой при запуске и вызывайте `bb.sdk.hosts.experimental_suspend({ hostId })` по истечении срока. Ядро ждёт завершения активной работы до пяти минут, прежде чем вызвать ваш `suspend`. «A dispatch hook can help communicate status but is bypassable and does not protect terminal/file RPCs.»

**availability.** Каждая проверка выполняется в пределах таймаута решений плагина (по умолчанию `DEFAULT_PLUGIN_HOOK_TIMEOUT_MS`, 10 с); некорректный вывод, исключение или таймаут считаются недоступностью.
