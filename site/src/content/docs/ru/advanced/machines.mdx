Провайдер машины позволяет плагину создавать вычислительные ресурсы, и разделение труда с core строгое: «core owns enrollment, the identity files and the internals of installing the daemon», и «machine plugins do not clone projects».

После подключения новой машины core сам настраивает git remote проекта и регистрирует его источник и только потом вызывает провайдера окружения, которому нужен `projectCheckout`. Машина не привязана к проекту: «nothing in its creation names a project, and projects reach the machine later through project sources».

**Порядок.** `validate`/`availability` → `create` (идемпотентно по ключу) → `await checkpoint(resource)` → `bootstrap({ key, executor, report, signal })` → вернуть `{ status:"created", name, resource }`.

**Удаление.** `remove({ hostId, resource, … })`, когда checkpoint есть; `reconcileCleanup({ key, … })`, когда его нет, — «find and remove indeterminate allocations by the durable key; return failed until the allocation intent is resolved». Удаление постоянной машины сначала каскадом проходит через провайдеров окружений; удаление ephemeral-машины пропускает teardown и никогда не возобновляет приостановленные вычислительные ресурсы.

**Простой.** Тайминг простоя — ваша забота, а не core: `experimental_thread.events` + `experimental_terminal.input`, чтобы продлевать дедлайн, и `bb.background.schedule` плюс сверка при старте, чтобы подчищать. «The dispatch hook helps report status, but it is bypassable and does not protect terminal/file RPC.»

**availability.** Проверки идут параллельно, у каждой дедлайн 5 s; «malformed output, exceptions and timeouts all look like unavailable», а «a registered provider is not by itself enough».
