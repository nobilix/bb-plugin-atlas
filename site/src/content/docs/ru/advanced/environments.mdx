С помощью провайдера окружения плагин управляет тем, где находится рабочий каталог треда, а ядро отвечает за перемещение по нему. Ниже описаны переходы жизненного цикла, что добавляет создание, claimPath, availability и специфика ворктри.

```
// docs/lifecycle-diagrams.md — the transitions (source packages/domain/src/environment-lifecycle.ts)
start        ──▶ creating
creating     ──provision.requested──▶ provisioning
creating     ──provision.failed | provision.cancelled──▶ error
creating     ──destroy.recorded──▶ destroyed
provisioning ──provision.succeeded | provision.cancelled (workspace on disk)──▶ ready
provisioning ──provision.failed──▶ error
provisioning ──provision.cancelled (no workspace)──▶ destroyed
ready | error ──provision.requested──▶ provisioning
ready | error ──destroy.recorded──▶ destroyed
// A MISSING edge = the event is a no-op in that status (the writer returns illegal-transition)
```

**Что добавляет создание.** Пять колонок в `environments`: `ownerThreadId`, `attempt`, `claimPath`, `statusMessage`, `pendingLog`. Ошибки создания окончательны, автоматического повтора нет; явный повтор очищает предыдущую попытку и переиспользует строку.

**claimPath.** В контекстах создания и восстановления `experimental_claimPath` возвращает false, если путь на этом хосте занят другим непривязанным запуском, если попытка уже не в `creating` или если для неё уже был занят другой путь; повторный запрос того же пути завершается успешно. «Check existing attached threads after claiming and before mutating a shared checkout.»

**availability.** Проверяется в фоне для списков выбора и повторно при создании треда, в пределах таймаута принятия решений, только для выбранных провайдера и машины. **Не проверено:** в документации есть разногласия о том, можно ли использовать кешированный ответ во время создания.

**Специфика ворктри.** Ворктри находятся в `<BB_DATA_DIR>/plugins/environment-git-worktree/host-data/worktrees/<thread-id>/<repo-name>`; `.worktreeinclude` (синтаксис gitignore) копирует неотслеживаемые локальные файлы после создания и до `.bb-env-setup.sh`; bb именно копирует файлы, а не создаёт симлинки, никогда не перезаписывает то, что уже есть в ворктри, и пропускает симлинки в источнике. Архивирование последнего треда запускает пятиминутный льготный период, а не удаление.
