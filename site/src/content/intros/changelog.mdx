This page shows bb's release notes from 0.0.29 to 0.49.0, the pinned release, and the rule by which experimental API stabilizes. The entries are `CHANGELOG.md` at the pinned commit, parsed by upstream's own parser and shown in full: 22 releases. What a plugin author acts on sits in the plugin section of each recent release (Plugins; CLI and plugins in 0.45.0; New plugin APIs in 0.44.0), and in 0.46.0, 0.47.0, 0.48.0 and 0.49.0 a "For plugin authors upgrading" entry names what an existing plugin must change.

:::note[The stabilization rule]
"Every public plugin API member ships with an `experimental_` prefix and an entry here… Stabilizing means auditing the entry, renaming project-wide, and deleting the entry in the same change".
{/* permalink: docs/api_to_audit.md */}
Each entry summarizes the API, names the file that documents its behavior on a "Docs:" line, and lists what must be settled before the prefix drops. The registry has 174 second-level sections, six of them records of retired members. An entry that stays experimental after an audit says so with the date and the open question; many carry "Kept experimental (2026-08-22)". For the renames and retirements in 0.48.0 and 0.49.0, built plugins keep working and the plugin build warns with the replacement.
:::
