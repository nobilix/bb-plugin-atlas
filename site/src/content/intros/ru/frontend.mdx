Справочник по клиентскому API: билдер и шесть его поверхностей регистрации, 32 метода-слота, хуки, встраиваемые компоненты хоста, стилизация и изоляция сбоев. У `@get-bb/plugin-sdk/app` нет собственного рантайма: пакет читает `globalThis.__bbPluginRuntime.pluginSdkApp`, а при сборке спецификатор импорта заменяется шимом на этот же глобальный объект. Поэтому бандл плагина работает только внутри bb, а импорт пакета за пределами хоста возвращает `undefined`, не роняя загрузку модуля.

## Билдер: шесть поверхностей регистрации

```ts
// app-contract.ts
export type PluginAppSetup = (app: PluginAppBuilder) => void;
export function definePluginApp(setup: PluginAppSetup): PluginAppDefinition;
// PluginAppDefinition = { readonly __bbPluginApp: true; readonly setup: PluginAppSetup }

app.experimental_icons        // ExperimentalAppIcons        experimental
app.commands                  // PluginAppCommands           stable
app.slots                     // PluginAppSlots — 32 methods stable
app.composer                  // PluginAppComposer           stable
app.contentScripts            // PluginAppContentScripts     stable
app.experimental_sidebarFooter// ExperimentalSidebarFooter   experimental

// app.hooks, app.settings and app.status do NOT exist: declarative settings
// and plugin status live on the backend only
```

{/* permalink: definePluginApp */}

Хост проверяет метку (brand) перед интерпретацией бандла и при каждой (ре)интерпретации заново вызывает `setup` с чистым коллектором, заменяя все регистрации плагина. Вызов setup происходит синхронно и валидируется; если валидация не прошла, остаётся предыдущая генерация.

### Проверки коллектора

- Идентификаторы слотов, панелей, вкладок, команд и элементов футера: `/^[a-zA-Z0-9_-]+$/`
- `messageDirective.id`: `/^[a-z][a-z0-9]*(-[a-z0-9]+)*$/`
- `timelineRenderer.kind`: `/^(tool|[a-z0-9-]+\/[a-z0-9-]+)$/u`
- `navPanel.path`: тот же шаблон, что и для идентификатора («it becomes a URL segment»)
- `fileOpener.extensions`: каждое значение `/^[a-z0-9]+$/`, в нижнем регистре и без точки
- Неизвестные поля регистрации отклоняются; переименованные ключи nav-panel отклоняются с подсказкой о новом имени
- Идентификаторы уникальны внутри вида слота; команды делят единый неймспейс между `app.commands.register` и устаревшим `app.slots.commandPaletteAction`
- `layout` принимает только значения `"padded"` или `"flush"`; `run`/`isAvailable`/`mount`/`onActivate` обязаны быть функциями

Собранная структура — `CollectedPluginAppRegistrations`, те же 38 корзин, которые тестовый harness возвращает как `CapturedPluginApp`.

Хуков `useTheme`, `useThread`, `useProject` и `useRoute` не существует. Хук `experimental_useSidebarThreadPullRequest` упразднён: кастомная строка плагина отображает состояние пулреквеста через `experimental_ThreadRowMetadata`. `PluginSidebarThreadIndicator` — это уже вычисленный тип статуса (`"unread-error" | "waiting-for-input" | "working-draft" | "workflow" | "background-agent" | "background-command" | "plan-mode" | "runtime" | "queued-failed" | "draft" | "unread-success" | "queued-waiting" | "none"`). В SDK нет готового компонента для статуса: отрисуйте собственный глиф, а незнакомые значения воспринимайте как `"none"`, поскольку bb со временем добавляет новые типы.

### `useComposer()`: куда попадают записи

```ts
// app-contract.ts
scope · key · layout · isRunning · isSubmitting · isSubmittingBlocked · isEmpty
text · draft · selection · replace · insert · setTextEffect · setInputLock
onSubmitted · focus · submit · setSelection
experimental_openPopup · experimental_closePopup
// older names kept at runtime: setText · updateText · clear · addQuote · insertMention ·
// removeMention · experimental_submit · experimental_setSelection · …

// which composer: inside a composer slot, that composer; in a thread's panels, that
// thread's composer; elsewhere, the current route's draft (the thread in view, or the
// new-thread draft). A handle always writes to its own composer's draft; thread and
// new-thread drafts persist, so a write after the composer left the screen still lands.
// setTextEffect and setInputLock are scoped to the CALLING plugin and lift themselves
// when the slot unmounts or the composer's scope changes.
```

`submit` выполняет реальную отправку через собственные обработчики send и steer композера, поэтому вложения, @-упоминания и (в новом треде) выбор провайдера, модели, уровня reasoning, тарифа (tier), разрешений и окружения передаются вместе с ним — плагин не может собрать этот кортеж сам. Метод реджектится при пустом черновике, если композера нет на экране, а также в редакторах поставленных в очередь и отправленных сообщений. `setSelection` задаёт значения в пикерах так, будто их выбрали вручную, и завершается после фиксации выбора; ожидание каталога ограничено 15 секундами. Метод реджектится в композере без пикеров (редактор сообщения в очереди, боковой чат, поверхность плагина вне какого-либо композера).

| `experimental_ProviderIcon` | `{ providerKind, provider: { id, logoUrl?, icon?, strings? }, fallback? (Code), className? }` | `experimental_` |

- Для компонентов `experimental_*` обязателен алиас в JSX: JSX воспринимает имена со строчной буквы как встроенные HTML-элементы, и `<experimental_Diff />` просто не скомпилируется. Переименовывайте их при импорте: `import { experimental_Diff as Diff, experimental_FileLink as FileLink } from "@get-bb/plugin-sdk/app"`.
- `ThreadChat` — сознательное исключение из правила «the SDK ships no UI kit»: хост сам управляет загрузкой таймлайна, стримингом, черновиками, отправкой/очередью/управлением/остановкой (send/queue/steer/stop), вложениями, элементами управления выполнением, ожидающими взаимодействиями (pending interactions) и отметками о прочтении. Не проксируйте данные треда через собственный RPC. Значение `permissionPolicy: "inherit"` (по умолчанию) привязывает отправку к разрешённому для треда дефолту и отключает пикер, поэтому поверхность плагина не может расширить права доступа.
- `experimental_Diff` получает общий пул воркеров подсветки синтаксиса из контекста React: в панелях треда и навигационных панелях он есть, а в секциях главной страницы и настроек — нет, поэтому код там рендерится без подсветки, но не падает с ошибкой.
- `experimental_NewThreadComposer` позволяет выбрать параметры, но тред создаёт ваш плагин. Черновик очищается после успешного завершения `onSubmit` и сохраняется, если возникла ошибка. Пропсы `default*` служат начальными значениями и сравниваются по значению при каждом рендере: изменение любого из них после монтирования сбрасывает весь выбор заново, включая то, что пользователь настроил вручную.
- Удалено: старые компоненты `EmptyState`, `PageBody` и `Spinner` убраны. Пишите свои; примеры реализации есть в `plugins/github/components/`.

## Стилизация: изолирование скоупа, шимы, токены

```ts
// packages/plugin-build/src/scope-plugin-utilities.ts
export function pluginScopeRoots(pluginId: string): string {
  return `[data-bb-plugin="${pluginId}"], [data-bb-plugin-root]:not([data-bb-plugin])`;
}
// the effective selector:
// :where([data-bb-plugin=<id>],[data-bb-plugin-root]:not([data-bb-plugin]))
// :where() keeps the scoping from adding specificity.
// The host wrapper sets the attributes: PluginSlotMount.tsx renders
// <div data-bb-plugin-root="" data-bb-plugin={pluginId} className="contents">
```

- Переписывается только блок `@layer utilities`, и каждое правило получает две ветки: селектор-потомок `${scope} ${selector}` и составной селектор `${scope}${selector}`; для `+`/`~` остаётся только ветка потомка. Правило класса вне слоя utilities приводит к сбою сборки, поскольку оно утекло бы на страницу хоста.
- Директива `@scope` намеренно не используется из-за накладных расходов на пересчёт стилей (style-recalc) в WebKit; правило репозитория в `AGENTS.md` напрямую ссылается на этот файл.
- bb отдаёт стили плагина без второй ветки (`dropAnonymousPluginRootScope`), поэтому они соответствуют только собственному UI плагина. Файл `app.js`, который устанавливает `data-bb-plugin-root` без `data-bb-plugin`, сохраняет более медленный устаревший скоуп, о чём сборка выдаёт предупреждение.
- Собственный `app.css` плагина конкатенируется после изолированного вывода и не изолируется скоупом.
- Время жизни таблицы стилей: тег `<link rel="stylesheet" data-bb-plugin-css="<id>">` в `document.head` управляется подсчётом ссылок с задержкой в 1500 мс при освобождении, а `usePluginCss` вызывается внутри `useInsertionEffect`. Это не глобальный хук для стилей приложения: общесистемные палитры объявляются через `bb.themes` в манифесте.
- Цвета: только классы токенов Tailwind от хоста (`bg-card`, `text-foreground`, `text-muted-foreground`, `border-border`, `text-destructive`). Никаких кастомных цветов `@theme`, написанных вручную `oklch(...)` или литералов серого цвета: проход Tailwind при сборке генерирует утилитарные классы только для темы по умолчанию, а захардкоженные цвета ломают пользовательские палитры. Каждый режим задаёт два якоря — `--canvas` и `--ink`, а остальные нейтральные оттенки вычисляются через `color-mix`; вам не нужно читать их напрямую.
- Компоненты вендорятся стандартным shadcn из реестра bb: `npx shadcn add @bb/select @bb/table`. Команды `bb plugin vendor` не существует. Единственное отличие от стандартного shadcn: `Dialog` на компактных экранах рендерится как нижняя шторка (drawer) с тем же API.
- Выражение `import { toast } from "sonner"` перенаправляется шимом на хостовый Toaster; никогда не монтируйте собственный `<Toaster>`. Для кода и диффов используйте `experimental_SourceCode`/`experimental_Diff`, а не `@pierre/diffs` напрямую: иначе нормализацию патчей и тему кода придётся поддерживать самостоятельно, а компонент выпадет из установленных замен рендереров.

## Изоляция сбоев

| Сбой | Что видит пользователь |
|---|---| 
| исключение при рендере аддитивного слота | плашка crash chip «plugin `<id>` crashed» или ваш собственный `crashFallback` |
| исключение в слоте замены | откат к собственному компоненту bb через `crashFallback={<PluginOwnerRenderer />}` |
| исключение в списке тредов или навигации боковой панели | интерфейс bb плюс toast |
| исключение внутри `messageDirective` | исходный текст директивы |
| не удалось загрузить бандл | `status: "failed"`, зафиксированная генерация деактивируется, регистрации и CSS отзываются |
| исключение в `setup` | предыдущая генерация деактивируется, регистрации и CSS не публикуются |
| content script упал с ошибкой или не уложился в лимит 10 с | кандидат отменяется, уже смонтированные скрипты откатываются в обратном порядке, ничего не публикуется |

{/* permalink: PluginSlotMount.tsx */}

Граница ошибок (boundary) индексируется ключом `${pluginId}/${slotKind}/${slotId}[/${instanceId}]`, и ключ со сбоем попадает в карту уровня модуля `crashedSlotInstances` вместе с ключом сброса слота. Слот остаётся неактивным до конца сессии, пока не изменится его ключ сброса или пока `resetCrashedPluginSlots(pluginId)` не очистит его при перезагрузке. Диагностика публикуется как `lastFailure.phase: "load" | "setup" | "mount" | "dispose"`. Сбой одного плагина не может сорвать активацию другого. Чтобы не падать с ошибкой, у каждого слота замены есть привязанный к конкретному вызову компонент `Original`: слот может делегировать ему отрисовку, не входя повторно в цикл разрешения замен; `experimental_Original` был устаревшим алиасом, удалённым в bb 0.42.

## Слоты: карточка для каждого

Виды слотов: **аддитивные** (располагаются рядом с другими плагинами и интерфейсом bb), **заменяющие** (замещают компонент bb и откатываются к нему при сбое), **эксклюзивные** (один плагин на всю область) и **хостовое обрамление** (плагин не передаёт компонент, bb отрисовывает его сам).
