# `site/`

Astro + Starlight. Static output, English at the root and Russian under `/ru/`, no hard-coded origin.

## Commands

Run them from the repo root; `site` is a pnpm workspace member.

| Command | What it does |
|---|---|
| `pnpm --filter site dev` | Dev server on `http://localhost:4321`. Search does not work here: Pagefind indexes the built HTML, so it only exists in a production build. |
| `pnpm build` | Static build into `site/dist`, including the Pagefind index. |
| `pnpm --filter site preview` | Serve `site/dist`. The only way to test search. |
| `pnpm typecheck` | `astro check` across `.astro`, `.ts` and `.tsx`. |

`SITE_URL` is the deploy origin. Every internal link is relative, so it is used only for the absolute URLs in `llms.txt` and the sitemap; it defaults to `http://localhost:4321`. Copy `.env.example` to set it locally, and set the repository variable for the deploy.

Astro and Starlight are pinned to exact versions: Starlight ships breaking changes in minors (0.39 changed sidebar autogeneration, 0.41 required Astro 7, 0.42 rewrote the mobile menu). A caret would be a silent redesign on some future install.

## Routes

| Route | Source |
|---|---|
| `/`, `/concepts/`, `/architecture/`, `/start/`, `/choose/`, `/testing/`, `/trust/`, `/package/`, `/cli/`, `/runtime/`, `/glossary/`, `/about/`, `/advanced/*` | prose in `src/content/docs/` |
| `/surfaces/`, `/frontend/`, `/backend/`, `/plugins/`, `/changelog/` and their detail pages | generated by `src/pages/[...lang]/` from `data/*.json`; each index opens with the prose in `src/content/intros/` |
| `/map/` | the zone map, `src/pages/[...lang]/map.astro` |
| `/<path>.md`, `/briefs.json`, `/llms*.txt` | agent endpoints, see below |

The content-layer loader in `src/loaders/atlas-json.ts` validates every `data/*.json` file against the Zod schemas in `@atlas/core` before a page renders; a mismatch fails the build. Counts on generated pages are read off the data, never typed: `/frontend/` lists the `PluginAppSlots` methods and the `PluginAppBuilder` regions under separate headings and never sums them. Every SDK symbol links to the pinned commit through `@atlas/core`'s permalink helper; a symbol the sync could not resolve renders as plain code rather than as a wrong link.

## Locales

English is Starlight's root locale, Russian is `ru`. Starlight's language picker lands on the same path in the other locale, generated pages included. Every page exists in both; `tests/integrity.test.ts` fails when one does not.

| What | English | Russian |
|---|---|---|
| Prose | `src/content/docs/<path>.mdx`, `src/content/intros/<id>.mdx` | the same under `ru/`, translated under the contract in `docs-internal/TRANSLATION-RU.md` |
| Interface chrome | `src/i18n/ui.ts`, `en` | the same file, `ru`; a missing key falls back to English |
| Surface and group text | `data/surfaces.json` | `translations/ru/surfaces.json`, used only while its `sourceHash` matches the English record (`src/lib/overlay.ts`); stale or missing means English |
| Upstream text: namespace docs, plugin descriptions, changelog entries, annotations, rules | English | English, quoted |
| Everything an agent copies: briefs, the bb mention, `/briefs.json`, `/llms*.txt` | English | English |

Pagefind builds one index per `<html lang>`, so a Russian page searches Russian pages.

## Agent endpoints

| URL | What it serves |
|---|---|
| `/llms.txt`, `/llms-full.txt`, `/llms-small.txt` | from `starlight-llms-txt`; the docs collection only, in English |
| `/<path>.md` | any page as raw Markdown; `/` at `/index.md`, `/ru/` at `/ru.md` |
| `/briefs.json` | every surface, slot and namespace as a brief, with the pin it was generated at |

"Copy page as Markdown" in the page header fetches that page's `.md` twin. The generated reference pages are not in `llms.txt`; they are reachable through `/<path>.md` and `/briefs.json`.

## Design

`src/styles/tokens.css` holds the palette and overrides Starlight's CSS variables; `src/styles/theme.css` applies them to Starlight's markup. Light-first, near-monochrome, 1px hairlines, no shadows, no gradients, charcoal as the only filled button, emerald and cobalt only as small accents. Starlight ships dark-first, with its dark values on `:root` and light behind `:root[data-theme='light']`; the tokens invert that priority, and Starlight's own theme toggle drives both.

## Islands and JavaScript

React is opt-in per component. A Starlight page costs about 11 KB of JS; one `client:load` React island adds about 216 KB to the page it lands on. So no island goes in a shared layout, and `/map/` is the only page that mounts one: a generated reference page ships about 18 KB, `/map/` about 248 KB.

| Component | What it is | Where |
|---|---|---|
| `DiagramBoard.astro` | CSS-grid boxes with an SVG connector layer measured after layout; a vanilla `<script>`, since one measured redraw with no state needs no runtime. Boards are data in `components/boards.ts`. The prose marks a board with an MDX comment, and `remark-diagram-board.mjs` rewrites it into the component. | `/concepts/`, `/architecture/`, `/start/`, `/runtime/` |
| `ZoneMap.tsx` | The one React island. The seven screens are server-rendered by `zonemap/Screens.astro` and passed in as children; the island measures them and owns the overlays, the fixture switcher and the hash route. Its strings arrive as a prop for the page's locale, so neither dictionary is bundled. | `/map/` |
| `BriefActions.astro` | The agent brief, the bb mention and "add to set", as a custom element; both payloads are rendered at build time and travel as JSON in the page. | surface, slot and namespace pages |
| `BriefBasket.astro` | The set panel. One `localStorage` key, `atlas.basket`. `renderBasket` is a dynamic import, because the module that holds it also holds the annotation bank, which Rollup keeps. | the same pages, and `/map/` |

Starlight's `.sl-markdown-content` puts `margin-top: 1rem` between adjacent elements at a specificity a single-class rule cannot outrank. Both `DiagramBoard` and `ZoneMap` carry Starlight's `not-content` class, which exempts their descendants; anything added inside them keeps it. `overflow-x: hidden` is not used anywhere: it hides sideways overflow instead of fixing it, and long identifiers in page titles are allowed to break and shrink on narrow viewports instead.
